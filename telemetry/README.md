# Telemetry Collection

Elastic Agent collected Windows and Linux telemetry for centralized searching, detection, and investigation. The committed YAML files are real applied-policy snapshots, not clean Fleet import packages.

## Windows Applied Policy

![Windows Telemetry Integrations](../evidence/telemetry/windows-telemetry-integrations.png)

The Windows policy snapshot proves:

- System integration streams for Windows Application, Security, and System logs.
- `win-sysmon` reads `Microsoft-Windows-Sysmon/Operational`.
- `win-defender` reads `Microsoft-Windows-Windows Defender/Operational`.
- The Defender input explicitly configures Event IDs `1116,1117,5001`.
- Elastic Defend uses the `EDRComplete` preset.

[Inspect the Windows applied-policy snapshot](../artifacts/fleet/windows-applied-policy.yml).

### Defender Evidence Boundary

![Windows Defender Events](../evidence/telemetry/windows-defender-events.png)

The Kibana screenshot shows Defender Event ID `5007` records were searchable. The exported Fleet policy does **not** configure Event ID `5007`; therefore the screenshot proves observed data, while the policy proves only the configured IDs `1116`, `1117`, and `5001`.

### Sysmon

![Sysmon Process Creation](../evidence/telemetry/sysmon-process-create.png)

The screenshot shows one Sysmon Event ID `1` process-create event. The deployed configuration was the third-party Olaf Hartong Sysmon Modular balanced configuration; it was not authored for this project.

[Inspect the attributed Sysmon configuration](../artifacts/sysmon/sysmon-modular-balanced.xml).

## Ubuntu Applied Policy

![Ubuntu Fleet Policy](../evidence/telemetry/ubuntu-fleet-policy.png)

The Ubuntu System integration snapshot proves logfile collection from:

- `/var/log/auth.log*`
- `/var/log/secure*`
- `/var/log/messages*`
- `/var/log/syslog*`
- `/var/log/system*`

These streams feed the `system.auth` and `system.syslog` datasets. The policy also contains conditional cross-platform inputs generated by the System integration; those do not mean Windows telemetry was collected from Ubuntu.

[Inspect the Ubuntu applied-policy snapshot](../artifacts/fleet/ubuntu-applied-policy.yml).

![Ubuntu SSH Events](../evidence/telemetry/ubuntu-ssh-events.png)

The screenshot separately proves SSH authentication events were ingested and searchable.

## Fleet Evidence

## Telemetry and Fleet Management Boundary

```text
Windows / Ubuntu Elastic Agents → Elasticsearch → Kibana / Elastic Security

Kibana Fleet UI ↔ Elasticsearch Fleet state ↔ Fleet Server ↔ Elastic Agents
```

Fleet Server manages enrollment, policy delivery, actions, status, and lifecycle. It is not the endpoint-telemetry relay, telemetry store, or analysis engine.
